# 真果鉴

多站源短剧浏览与在线播放应用，Android 手机版。基于开源项目 [Topkill/guoapp3](https://github.com/Topkill/guoapp3) 二次开发与改版。

当前版本：**0.8.7+82** ｜ 平台：Android 7.0+（arm64-v8a / armeabi-v7a） ｜ [下载最新版](https://github.com/ai0by/zhenguojianTV/releases/latest)

---

## 一、这是什么

一款聚合多个短剧站源的客户端：浏览、搜索、详情、选集、在线播放、下载与合并，**全部在手机本地完成**，不依赖任何自建服务器或中转。

- **站源解析**：设备端直接请求各站源接口，不经过第三方中转。
- **数据存储**：剧库、追剧、观看历史、下载记录都保存在本机。
- **账号**：没有云端账号，不需要登录；只有本机用户与权限管理。

## 二、更新（0.8.7）

### TV 版式收紧

- **电视返回键去重**：一次按键不再同时走键盘事件和系统返回，"多退一级"消失。
- **退出确认改为双击返回**：首页按返回先提示「再按一次退出」，不再弹会被下一次返回重新弹出的对话框。
- **电视顶部栏移除**：站源、搜索、设置挪进左侧菜单；榜单、排序、更新并到剧类行右侧。
- **电视控件整体缩小一档**：按钮、字号、选集面板、站源弹窗、屏幕键盘统一收紧，720p 盒子一屏能多放一行。
- **海报与剧集卡片按 2:3 反算高度**：封面不再被裁掉上下两端，卡片底部标题与集数也不再溢出。
- **焦点滚动跟随方向**：列表底部往上一格会正常向上滚动，不再卡住。
- **电视隐藏返回箭头**：各页面顶部不再出现多余的返回上级按钮（遥控器自带返回键）。
- **编译改走 GitHub Actions**：新增 `Build APK` 工作流，手动触发即可出包，本机不用装 Flutter / Go / NDK。

### 新增站源：51短剧

- **接入方式**：`blue.xdrgcewe.cc` 是 Nuxt 3 站点，列表页与详情页都把数据放在 `<script id="__NUXT_DATA__">` 里，内容是 devalue 序列化的「扁平数组 + 下标引用」，必须先解引用才能拿到真实对象。新增 `provider_51duanju.go` 实现了解引用、卡片提取与分集解析。
- **一次请求拿全部分集**：详情页 payload 的 `episodeAll[].video_url` 直接带每集播放地址，不需要逐集抓页面（黄果那套要按集请求，这里省掉 N 次往返）。
- **播放地址必须原样保留 `auth_key`**：截断成 `.m3u8` 会被 CDN 判 400，所以不做任何清洗，交给流代理改写。
- **AES-128 HLS 直接可播**：`#EXT-X-KEY` 指向另一个带 `auth_key` 的密钥地址，现有代理已经会重写 `EXT-X-KEY` / `EXT-X-MAP` 的 URI，不需要为这个源单开分支。
- **分类**：首页推荐、排行榜、剧场、最新；支持站内搜索与分页。
- **权益字段**：站点用 `unlocked` / `access_reason` / `state` 描述单集权益，解析时按这三个字段判定是否标记 VIP，避免把免费集误标成付费。
- **镜像策略**：该站换域名很勤，旧域名会 301 到停靠页（实测 `51dj29.com` → `hoamqvgal.cc` 已非原站）。内置只保留当前可用地址，新域名走 `config/source_mirrors.json` 的 `51duanju` 段热更新。

### 站源地址维护

- **黄豆补 9 个镜像域名**：从第三方维护的域名池与 TVBox 蜘蛛脚本里收集，逐个实测 `GET /home` 200、`POST /api/drama/list` 200，与 `tideember.cc` 同后端；`nbsito.top` 已失效未收录。
- **黄果补 3 个泛解析入口**：`*.ediayikma.cc` 是泛解析，随机子域名与 `thu.` / `pku.` 行为一致（根路径 200、`/detail/` 与 `robots.txt` 同响应），不再只依赖固定的几个前缀。
- **镜像域名识别改成查表**：原来 `providerSourceForURL`、`canonicalProviderSource`、`nativeCoverReferer` 三处各自硬编码 `tideember.cc` / `xqjurgek.top`，新增域名会认不出来，导致换源失效、封面 Referer 丢失。现在统一走 `huangdouBaseMirrors`。
- **远程配置仍然是热更新**：`config/source_mirrors.json` 由 jsDelivr 拉取，改完推 `main` 后已安装的 App 一小时内自动生效，不必重新出包；内置列表只在拉取失败时兜底。

### 播放与镜像健壮性

- **无扩展名 M3U8 不再断流**：部分镜像把播放列表以 `application/octet-stream` 返回、地址也没有 `.m3u8` 后缀，原来只按 Content-Type 和后缀判断会漏判，漏判后相对分片地址不会被改写成本地代理地址，播放直接断。现在补了 `#EXTM3U` 正文嗅探（只预读 64 字节，不会把视频读进内存）。
- **旧任务的播放地址会跟着换域名**：存量任务里存的页面地址可能还是上一代域名（黄果旧站 `huangguo.video` 现在直接 404），播放时先按当前站源基址重新拼接主机，失败再退回原地址。
- **黄果旧站详情走镜像配置**：详情页原来写死 `huangguo.video` 常量，远程镜像和用户配置对它都不生效；现在与黄果 AI 一致走 `providerBaseURL`。
- **浏览器指纹客户端跟随显式配置**：指纹传输原来只认死 `huangguo.video`，配置了自建镜像/联调地址会退回普通 client（过不了 Cloudflare，也连不上自签证书站点）。
- **代理探测不再空指针**：`proxyRouter` 未初始化时（纯直连场景）调用会 panic，补了判空。
- **回归门禁清零**：`go test ./core` 原有 6 个失败全部定位并处理——3 个是实现缺陷（无扩展名 M3U8、黄果旧站配置不生效、`proxyRouter` 空指针），3 个是用例本身过期或隔离不足（schema 版本、多分类 fixture、包级镜像缓存跨用例泄漏）；另外修掉榜单用例依赖真实 jsDelivr 的偶发失败。

### 0.8.6 起的既有能力

- **TV 遥控状态机收敛**：短按 OK 只执行一次播放/暂停并进入控件焦点；长按 OK 3 倍速、松开恢复，不再误触发暂停。

- **回归门禁补齐**：新增真实遥控按键 Widget 测试、站源镜像路由测试、完整 TV 流程清单与全量 Flutter 回归。

## 三、快速开始

1. 从 [Releases](https://github.com/ai0by/zhenguojianTV/releases/latest) 下载 `zhenguojian-<版本>-arm64-v8a.apk`。
2. 手机上安装（需允许「安装未知来源应用」）。
3. 打开即用；App 不进行自动更新检测，后续版本请自行查看 Releases。

要求：**Android 7.0 及以上（minSdk 24）**；手机建议 64 位（arm64-v8a），电视盒子可用 32 位（armeabi-v7a）。
若安装提示 `INSTALL_FAILED_NO_MATCHING_ABIS`，表示设备架构与安装包不匹配。

## 七、常见问题

**Q：为什么剧库更新要很久？**
A：更新需要逐部复查详情。红果 2600 多部约 11 分钟、黄果 AI 2200 多部约 18 分钟，而单轮上限 10 分钟，所以会分批续跑。0.7.1 已把后台自动更新改为 2 小时间隔、可关闭；手动更新仍可随时执行。

**Q：黄果几个源有时更新失败？**
A：属网络可达性问题，不是解析错误 —— 黄果视频走 IPv6 且无备用域名，黄果 AI 的镜像域名会被重置。换网络或开代理后重试通常能恢复。

**Q：调了亮度，手机屏幕亮度没变？**
A：设计如此。只调整视频画面亮度，不动系统亮度，退出播放器后手机亮度不受影响。

**Q：为什么只提供 64 位安装包？**
A：目标设备（手机与投影仪）均为 arm64。32 位构建脚本保留，但不再发版。

**Q：支持电视 / 电脑吗？**
A：Android TV 已恢复适配（0.8.0）：遥控器导航、电视布局、过扫描安全边距、32 位盒子支持。Windows 版源码保留但当前不构建、不交付。
电视安装包用 `python3 scripts/build_android.py --tv --universal --all-sources` 构建（产出 arm64、armv7 分包，并额外产出包含两种 TV ABI 的 `-all.apk`）。若电视没被自动识别为电视（部分盒子定制 launcher、投影仪），在「更多 → 界面模式」里手动选「电视 / 遥控器」。

**Q：需要登录吗？**
A：不需要。没有云端账号；本机用户管理只用于区分不同使用者与权限。

## 十、开发与构建

环境：Flutter `3.47.4`、Dart `3.12+`、Go `1.24.1+`、Python `3.10+`；Android 需 JDK 17、SDK 36、NDK `28.2.13676358`。

```sh
# 全站源版（真果鉴）
python3 scripts/build_android.py --abi arm64-v8a --all-sources
# 仅红果版（红果鉴）
python3 scripts/build_android.py --abi arm64-v8a
# 电视版（arm64-v8a + armeabi-v7a 分包，并额外产出 universal/all APK）
python3 scripts/build_android.py --tv --universal --all-sources
```

- **必须在纯英文路径下构建**（中文路径会导致工具链失败）。
- 构建时不要设 HTTP 代理；访问 GitHub 时才需要代理。
- 产物在 `dist/android/`，`SHA256SUMS.txt` 为校验清单。

不用本机编译时，走 **Actions → Build APK → Run workflow**：`all_sources` 决定真果鉴 / 红果鉴，`tv` 产出 arm64-v8a + armeabi-v7a 分包，`universal` 额外产出合并 APK；跑完在本次运行的 Artifacts 里下载 `apk-<run_number>.zip`。工作流固定 Flutter `3.47.4`、Go `1.24.1`、NDK `28.2.13676358`，与本机脚本一致；未配置 `android/key.properties` 时用 debug 签名，可直接安装但不适合上架。

源码结构：

| 目录 | 内容 |
| --- | --- |
| `lib/` | 页面、播放器、本地用户、FFI、下载与媒体处理 |
| `native/core/`、`native/bridge/` | Go 站源核心、缓存、下载与 C ABI |
| `android/`、`windows/`、`ios/` | 平台工程与必要资源 |
| `scripts/`、`.github/workflows/` | 构建、签名、验证与版本快照 |
| `test/`、`integration_test/` | 自动化与设备回归 |

仓库只提交业务源码，不包含构建产物、依赖缓存、本地机器配置、签名文件与任何密钥。

播放器使用 [media_kit](https://github.com/media-kit/media-kit) / libmpv，合并与导出使用 [FFmpegKit min-gpl](https://github.com/sk3llo/ffmpeg_kit_flutter)（含 FFmpeg、x264 / x265 等 GPL 组件，适用上游许可证）。
