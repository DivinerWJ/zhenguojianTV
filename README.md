# 真果鉴TV

多站源短剧浏览与在线播放应用，Android 手机版。基于开源项目 [Topkill/guoapp3](https://github.com/Topkill/guoapp3) 二次开发与改版。

当前版本：**0.8.10+85** ｜ 平台：Android 7.0+（arm64-v8a / armeabi-v7a） ｜ [下载最新版](https://github.com/ai0by/zhenguojianTV/releases/latest)

---

## 一、这是什么

一款聚合多个短剧站源的客户端：浏览、搜索、详情、选集、在线播放、下载与合并，**全部在手机本地完成**，不依赖任何自建服务器或中转。

- **站源解析**：设备端直接请求各站源接口，不经过第三方中转。
- **数据存储**：剧库、追剧、观看历史、下载记录都保存在本机。
- **账号**：没有云端账号，不需要登录；只有本机用户与权限管理。

## 二、更新

### 0.8.10 · 播放与站源可用性

- **野果终于能播了**。根因是一处自锁：`/api/playlet/play` 拿到密文后要解密，解密需要先从 `_nuxt` 里发现密钥，而密钥发现要再发请求 —— 但源级并发门还被这次请求占着（响应体没关），于是发现一直在等自己，直到 25 秒超时，用户看到的是"野果整站不可用"。现在读完响应立刻释放门，且密钥发现整体跳过源级门（批量上限 8）。实测冷启动点播 **4 秒**拿到 m3u8，上游 200、AES-128 密钥可达。
- 密钥发现不再走镜像竞速：原来首页用竞速（候选 × 2 副本 × 3 波），一个坏镜像就能吃掉 20 秒；现在按候选顺序直取，失败就换下一个。
- **香蕉改为"正片不行就试试看"**。正片会话对游客一律 403 `purchase_required`，客户端没有合法路径拿全集；现在被拒后会再请求 `/api/trial/sessions`，拿到试看 manifest 就播试看片段，拿不到才提示需要会员。试看请求同样跳过退避门，否则刚被 403 挂上的退避会把兜底请求也挡掉。
- **香蕉列表恢复**。目录 / 搜索 / 详情这条路径一直匿名请求，一旦站点给列表接口加上游客鉴权就只剩 401，表现为"整站列表加载不出来"而播放反而是好的（播放自己会换 guest-sessions）。现在目录类请求匿名 401 时会自动补一次游客 token 再重试；另外目录拉取失败后**自动重试一次**，不再等用户进设置点「检查链接」。
- **香蕉不再报「443，connection reset by peer」**。站点本身是好的（Cloudflare 后面 A 记录正常），是**这条链路的 IPv6 出口被 RST**；而 Go 默认 Happy Eyeballs 优先 IPv6，IPv4 明明可用也轮不到，客户端就只剩一句 reset。现在香蕉的请求**首次就用 IPv4 拨号**，第二次回到默认（兜住"只有 IPv6 通"的反向情况），所以列表能进、搜索和详情也跟着好了。失败时提示也换成人话：「香蕉站源网络连接被中断（已自动改用 IPv4 重试仍失败，可试试切换网络或关闭代理）」，不再只丢一个 443 和 reset。
- **修掉"红果偶发一直转圈、下拉刷新永远失败"**。请求被 403 / Cloudflare 拦过一次后，限流器会给该 host 挂最长 30 分钟退避，此后所有普通请求在"抢门"阶段就直接失败，客户端只看到转不完的圈 —— 这也是"去设置里点一次检查链接就好了"的原因（检查链接走强制刷新，绕开了退避）。现在：强制刷新（下拉刷新 / 重试 / 检查链接）先清退避；**普通目录请求失败后一律清退避并自动重试一次**（原来只对退避类失败重试，覆盖不到真正偶发的超时 / 连接重置）；播放解析同样处理。
- **失败不再"一直卡着"**。退避期内连「更新剧库 / 检查链接」这类用户主动点的任务也会被挡回去，只能干等半小时 —— 现在主动任务（`update` / `check` / `more`）直接放行并清退避，只有后台资料补齐类任务（`metadata` / `vipMetadata`）继续守退避。更新横幅在失败时多了一个「重试」按钮（原来只能进设置点「检查链接」才能重来）；下拉刷新撞上"已有任务在跑"时也不再静默无反应，会明确提示正在更新。
- **多站源去掉一个后页面立刻刷新**。从多选退到单选时，代码会先把多选集合清空再调切换逻辑，于是"剩下的这个源恰好就是原来的单选源"会命中"没变化就返回"，页面继续停在多源聚合结果上。现在这条路径强制重载；同时进入多选时会关掉推荐流（否则紧接着的目录加载会在开头直接 return，一样不刷新）。

### 0.8.10 · 站源收敛、安装包与集数展示

- **香蕉（`xiangjiao`）暂时下线，入口不再展示**。目录 / 搜索 / 详情整条链路在客户端这一侧已经试到底了（补游客 token、IPv4 拨号、失败自动重试都做过），站点现在仍然不给列表数据，留着入口只会让人以为"这个源坏了"。现在只从**可展示**列表里摘掉：代码、native 侧、镜像配置一律不动，旧存档 / 局域网同步 / 下载记录里已有的 `xiangjiao:xxx` 仍能解析出「香蕉」而不会掉回红果；站点恢复后把它加回 `SourceSite.values` 即可。
- **修掉 all 版 APK 在手机上"解析软件包失败"**。三个原因一起修：
  - **半套 ABI**：all 包里带着一个不完整的 `lib/x86_64/` —— ffmpeg / media-kit 这些依赖的 AAR 自带 x86_64 的 `.so`，而 app 自身的 `libapp.so` / `libflutter.so` / `libduanju_core.so` 只按 ARM 两套编译，x86_64 目录缺了最关键的几个。这种"声明了某 ABI 却给不全"的包会让安装器按错误 ABI 校验后直接判解析失败，还白占十几 MB。现在通用包只打 `arm64-v8a` + `armeabi-v7a`（84.4 MB → 72.1 MB），打包脚本会**拦死**任何"未编译的 ABI"混进来。
  - **版本号倒挂**：`--split-per-abi` 会给分包加 1000/2000/3000 的 versionCode 偏移（arm64 是 2085），而通用包还是 85 —— 先装过任意分包再装 all 包，安装器看到的是**版本降级**，很多 ROM 直接弹"解析软件包失败"。现在通用包的 versionCode 加 4000，永远高于分包。
  - **签名每次都变**：没配 `key.properties` 时 AGP 用 `~/.android/debug.keystore`，这个文件在每台 runner 上都是新生成的随机密钥，于是每次构建签名都不同，安装器会判签名冲突。现在用 Actions 缓存把它固定下来（顺带显式打开 v1 兼容签名，兜住只读 META-INF 证书的老安装器）。
  - 出包后 CI 会用官方工具逐个验：`apksigner verify`（并**断言 v2 为 true**）、`zipalign -c 4`（对齐）、`aapt2 dump badging`（minSdk、versionCode 与 ABI），任何一项不过就直接失败，不再"文件生成了就当成功"。
- **"共 X 集"补全**。有几个源其实给了集数，只是形式不统一：`更新至80集`、`共 80 集`、`全80话`、`80集全`、字符串 `"80"`、浮点 `80.0`。原来一律按整数解析，带一个汉字就归零，卡片上于是没有集数。现在先按数字解析、失败再取第一段连续数字，并把 `total_episodes` / `episode_num` 等别名一起收进来。
- **手机开屏换新图**。按美术新给的竖版成品图重新出 1080×1920（原图 941×1672，等比放大，JPEG q92）；新图从高度约 0.50 往下就是红色胶片带，品牌橙压上去看不见，所以手机端进度线改成**白色**并下移到 0.90 的深红区域，电视横版仍用品牌橙。
- **README 全篇统一「真果鉴TV」**（构建说明里的分支名也一并改），只保留「红果鉴」这条独立分发线不动。

### 0.8.10 · 开屏页、切集与解码

- **开屏页不再卡死**。原来"最长 3 秒"只是置位了最短展示时间，仍然要求首页拉到第一批视频才淡出；选中香蕉这类不可用站源、或者断网启动时它永远等不到，用户只能杀进程。现在超时是**硬超时**（2.2 秒）：时间一到直接进首页，首页自己显示错误与重试，离线也能进。
- **开屏换成美术成品图**。手机竖版 1080×1920、电视横版 1920×1080 各一张，按当前布局自动二选一，`BoxFit.cover` 铺满；只叠一条安静的进度线，不再是"永远转的圈"。淡出改成 240ms 真淡出（原来直接硬切），冷启动的原生窗口底色也换成同一浅色，从点击图标到进首页没有颜色跳变。
- **自动切集不再弹播放器**。自动连播切到下一集时不再把整套控件弹出来挡画面，要控件按一下确定/点一下画面即可；失败时仍会弹出来（否则摸不到重试）。**手动切集保持原样**（用户明确：只要求自动切集无感）。
- 预加载提前到**开播 1.2 秒**（原来 3 秒）：短剧一集常常不到一分半，用户又常常十几秒就滑走，越早准备越来得及。
- **电视不再误报"解码失败，已改用软件解码"**。原来"迟迟不起播"也算硬解坏的证据，弱网下切集起播慢两次（30 秒）就触发降级；现在起播慢只走恢复流程，只有"不缓冲、报告在播、却拿不到画面尺寸"这种强信号才降级，且要连续两轮。缓冲中的无画面交给换线路处理。

### 0.8.9 · 新增站源：E站番剧

- **接入方式**：`www.ezdmw.org`（含 `m.ezdmw.org` 镜像）是纯服务端渲染的动漫站，接口全明文、无签名，目录/搜索/详情/分集都用 HTML 正则解析，新增 `native/core/provider_ezdmw.go`。
- **播放链路**：分集页 → 弹幕播放器 iframe（`player.ezdmw.com/danmuku/`）→ 播放器里的 `<video src="…/index/listres/…webp">`。**这个 `.webp` 其实是 HLS 播放列表**（`Content-Type` 被写成 `image/webp`，正文是 `#EXTM3U`），分片再走 `ins.wdbed.vip/image.php?url=…` 中转。
- **修掉四个解析问题**：
  - **标题带空格的番剧全部播不了**。iframe 的 `src` 是把值原样写进 HTML 的，`title=` 里带中文和空格（`… 第四季`、`幼女战记 第二季`），Go 的 http 客户端把 `RawQuery` 原样写进请求行，空格把请求行截断 → 服务端回 400。实测首页 40 部里约一半受影响。现在只转义会破坏请求行的字符（空格、控制字符），**已有的 `%XX` 一律保留**——地址里有 `sign=` 签名，整体重编码会把 `%` 变成 `%25` 直接废掉签名。
  - **详情页封面是站点 logo**。详情页没有 `og:image`，第一个 `<img>` 是 `/Public/images/icon.png`。现在优先取 `Public/atlas_oss/…/some_img/<id>.jpg`，并跳过 `/Public/images/`、`/src/images/` 下的 UI 图标。
  - **目录标题混进元信息**。首页卡片的 `<a>` 里套着 `.info-card`，直接取整块文本会把"2星期前 更新到： 24 总追番数：118"当标题，HTML 注释被剥掉标签后还残留一个 `-->`。现在按「封面图 `title` → 标题 `<p>`（排除 `class` 含 info 的行）→ 整块文本兜底」取值，并覆盖首页三种卡片布局（最近更新 / 新番 / 排行榜）。
  - **目录集数恒为 0**。`更新到：&nbsp;24` 里是全角冒号 + 不换行空格，原来的 `\s*` 接不住，现在允许空白 / NBSP / 半角与全角冒号。
- **目录与搜索的分页**：站点的 `/` 和 `/Index/anime.html` 都忽略 `page`，`/Index/search.html` 更是把结果硬截断在 5 条，所以最初只能浏览首页 40 部、搜索最多 5 条。真正的分页入口是 `/Index/search_some.html`，它的 `page` 参数是**条目偏移量**而不是页码（站点每页写死 10 条，`page=10` 才是第 11 条起）。现在搜索走这个入口，可以一直翻到结果集末尾；目录首页仍是站点编排好的 40 部（最近更新 / 新番 / 排行榜），点「加载更多」后改用 `searchText=年` 继续枚举——搜索除了标题也匹配年份字段，而每部都有年份，所以「年」等价于全部番剧（实测约 2080 部）。页间重叠由客户端按 ID 合并去重，翻到底返回空页而不是报错。
- **站源侧的小毛病**：排行榜那 11 部没有封面，卡片显示占位图；`更至PV话` 这类没有数字的集数按 0 处理。

### 0.8.9 · 野果与香蕉：目录、搜索与分集修复

0.8.8 新增的这两个站源实测都有问题，这一版逐个修掉。

**野果（`yeguo`）**

- **分集标题串到别的剧、点播放报「剧集不存在或不属于该短剧」**。详情响应里 `related_list` 挂着别的剧，而解析器泛走整棵树、拿 `episode_id` 当键——站点真实的分集字段是 `id`（`episode_id` 恒为空），于是抓到的是别人的分集。现在只读剧级对象（`video_id` 与请求一致、带 `episodes[]`）里的 `episodes[]`，按 `sort` 排序。
- **首页要 110 秒**。原来要「每集真播一遍」才放行（32 部 ≈ 350 次请求）。实测 `content_access_type` 为 `free`/`coin`/`vip` 的剧集都能从 `/api/playlet/play` 拿到 m3u8，站点并没有在播放接口上拦付费，所以去掉逐集校验，也不再标 VIP（否则详情页会弹「这是一集 VIP 内容」）。首页从 110 秒降到 3 秒左右。
- **密钥发现时好时坏（实测 3/5 失败）**。镜像站会随机返回两种兜底页：一种是 `<meta name="style-origin">` + Base64 脚本，另一种整页只有 `document.write(Base64.decode("…"))`（解出来是「51短剧官方入口」，与野果无关）。镜像竞速只看「HTTP 200 且有内容」，兜底页会抢先赢下竞速。现在两种都识别为拦截页，而且**不触发域名退避**——它下一秒就可能恢复正常，一旦挂上 60 秒退避整个站源会直接不可用。同时把 `_nuxt` chunk 的抓取从镜像竞速改成同域直取（原来一个 chunk 最多 24 次请求，30 个 chunk 叠起来，站点一被拦就要跑几分钟），并给密钥发现加了 40 秒上限 + 失败后 60 秒不重试。
- **镜像裁剪**：`config/source_mirrors.json` 与内置列表都去掉 `ygdj16.com`、`hoamqvgal.cc`（一个只会返回挑战页，一个直接 EOF）。
- 搜索接口本身没问题（`keyword` + `page` + `limit`，实测「总裁」15 部）；之前「搜不到/搜出不相关」是密钥发现抖动导致的。

**香蕉（`xiangjiao`）**

- **目录混进分类名**。`/api/home/hot` 只返回 32 部，但解析器泛走整棵树，把列表项里嵌套的 `categories[]` / `primary_category`（`{id,name,slug}`）也当成剧集，于是变成 68 部，还混进「校园青春」「成人动漫」「明星换脸」。现在只读 `data.items`，并按 `type` / `commerce` / `slug` 过滤掉分类对象。
- **目录只有 32 部、翻页直接空**。改用 `/api/theater`（`total` 7000+，`limit=50` + `next_cursor` 分页），并按页缓存 cursor——站点没有 `page`/`offset`，要第 N 页只能顺次往前走。
- **搜索永远 0 条**。原来是对首页那 32 部做本地 `strings.Contains`。现在走 `/api/search?q=`，参数名就是 `q`（`keyword`/`query`/`term` 一律 400），并且查询串必须 URL 编码——直接塞中文会 400。
- **正片全部需要付费**：`/api/playback/sessions` 对正片回 403 `purchase_required`，客户端没有合法路径，所以分集标 VIP、点播时明确提示需要会员，不做绕过。
- 香蕉接口加了网络级重试：站点 IPv6 出口时不时 `connection reset by peer`，单次失败会让首页偶发空白。

### 0.8.9 · TV 焦点、返回键与播放器交互

- **焦点样式不再超出格子**：原来焦点是「四边 4px 内边距 + 3px 白描边 + 1.045 放大 + 外发光」，放大和外发光都画在控件边界之外，会被横向海报行的视口、封面的圆角、弹窗的滚动区裁掉——越靠边越明显（首尾两张海报、热门搜索的最后一个词、站源弹窗的最后一行）。现在所有焦点装饰都落在**自身矩形之内**：海报改四角标记，按钮/胶囊改紧贴内容的描边 + 填充，既没有被切掉的一半，也不再是悬空的框。
- **海报重新变大**：焦点不再预留 8px，封面按格子实际宽度铺满，`DramaTile.extentFor` 与电视海报行的高度反算同步按 0 处理。
- **返回键退回首页会把光标一起带回**：在发现 / 追剧 / 最近观看按返回，页面回首页的同时左侧菜单焦点回到「首页」，不再出现"界面已经在首页、光标还停在最近观看"。
- **发现页按返回不再误触退出**：部分盒子一次按键会同时产生键盘事件与系统返回，第二条事件到达时页面已经在首页，于是被当成"在首页按返回"直接提示退出。现在把电视返回键的去重窗口从 180ms 放宽到 400ms（实测重复事件间隔在 200ms 以内），同一次按键的第二条事件在入口就被丢掉，不会再往下逐层退让。
- **推荐分类先退一层**：发现页里打开的推荐分类算一层子页面，返回先退出分类，再退首页，不再一次连跳两级。
- **暂停后上下键仍能切集**：短按 OK 会把焦点交给播放按钮，此后方向键归焦点遍历管，上下键变成"在控件之间跳"，而控件只有一行，实际就是按了没反应。现在控件层就地截获上下键，语义与控件隐藏时完全一致（上/下一集）；底部控件同时合并成**一行**（播放 / 倍速 / 清晰度 / 选集 / 追剧 / 连播），左右键在按钮间移动即可，不会有按钮变得够不到。
- **恢复播放后控件会自动收起**：从控件按钮上恢复播放时把焦点还给页面，四秒后控件正常隐藏，不再一直挂在画面上。
- **电视去掉全屏按钮**：电视本身就是全屏，底部栏与全屏层的「全屏 / 退出全屏」按钮在电视模式下不再渲染。

### 0.8.7 · TV 版式收紧

- **电视返回键去重**：一次按键不再同时走键盘事件和系统返回，"多退一级"消失。
- **退出确认改为双击返回**：首页按返回先提示「再按一次退出」，不再弹会被下一次返回重新弹出的对话框。
- **电视顶部栏移除**：站源、搜索、设置挪进左侧菜单；榜单、排序、更新并到剧类行右侧。
- **电视控件整体缩小一档**：按钮、字号、选集面板、站源弹窗、屏幕键盘统一收紧，720p 盒子一屏能多放一行。
- **海报与剧集卡片按 2:3 反算高度**：封面不再被裁掉上下两端，卡片底部标题与集数也不再溢出。
- **焦点滚动跟随方向**：列表底部往上一格会正常向上滚动，不再卡住。
- **电视隐藏返回箭头**：各页面顶部不再出现多余的返回上级按钮（遥控器自带返回键）。
- **编译改走 GitHub Actions**：新增 `Build APK` 工作流，手动触发即可出包，本机不用装 Flutter / Go / NDK。

### 0.8.7 · 新增站源：51短剧

- **接入方式**：`blue.xdrgcewe.cc` 是 Nuxt 3 站点，列表页与详情页都把数据放在 `<script id="__NUXT_DATA__">` 里，内容是 devalue 序列化的「扁平数组 + 下标引用」，必须先解引用才能拿到真实对象。新增 `provider_51duanju.go` 实现了解引用、卡片提取与分集解析。
- **一次请求拿全部分集**：详情页 payload 的 `episodeAll[].video_url` 直接带每集播放地址，不需要逐集抓页面（黄果那套要按集请求，这里省掉 N 次往返）。
- **播放地址必须原样保留 `auth_key`**：截断成 `.m3u8` 会被 CDN 判 400，所以不做任何清洗，交给流代理改写。
- **AES-128 HLS 直接可播**：`#EXT-X-KEY` 指向另一个带 `auth_key` 的密钥地址，现有代理已经会重写 `EXT-X-KEY` / `EXT-X-MAP` 的 URI，不需要为这个源单开分支。
- **分类**：首页推荐、排行榜、剧场、最新；支持站内搜索与分页。
- **权益字段**：站点用 `unlocked` / `access_reason` / `state` 描述单集权益，解析时按这三个字段判定是否标记 VIP，避免把免费集误标成付费。
- **镜像策略**：该站换域名很勤，旧域名会 301 到停靠页（实测 `51dj29.com` → `hoamqvgal.cc` 已非原站）。内置只保留当前可用地址，新域名走 `config/source_mirrors.json` 的 `51duanju` 段热更新。

### 0.8.7 · 站源地址维护

- **黄豆补 9 个镜像域名**：从第三方维护的域名池与 TVBox 蜘蛛脚本里收集，逐个实测 `GET /home` 200、`POST /api/drama/list` 200，与 `tideember.cc` 同后端；`nbsito.top` 已失效未收录。
- **黄果补 3 个泛解析入口**：`*.ediayikma.cc` 是泛解析，随机子域名与 `thu.` / `pku.` 行为一致（根路径 200、`/detail/` 与 `robots.txt` 同响应），不再只依赖固定的几个前缀。
- **镜像域名识别改成查表**：原来 `providerSourceForURL`、`canonicalProviderSource`、`nativeCoverReferer` 三处各自硬编码 `tideember.cc` / `xqjurgek.top`，新增域名会认不出来，导致换源失效、封面 Referer 丢失。现在统一走 `huangdouBaseMirrors`。
- **远程配置仍然是热更新**：`config/source_mirrors.json` 由 jsDelivr 拉取，改完推 `main` 后已安装的 App 一小时内自动生效，不必重新出包；内置列表只在拉取失败时兜底。

### 0.8.7 · 播放与镜像健壮性

- **无扩展名 M3U8 不再断流**：部分镜像把播放列表以 `application/octet-stream` 返回、地址也没有 `.m3u8` 后缀，原来只按 Content-Type 和后缀判断会漏判，漏判后相对分片地址不会被改写成本地代理地址，播放直接断。现在补了 `#EXTM3U` 正文嗅探（只预读 64 字节，不会把视频读进内存）。
- **旧任务的播放地址会跟着换域名**：存量任务里存的页面地址可能还是上一代域名（黄果旧站 `huangguo.video` 现在直接 404），播放时先按当前站源基址重新拼接主机，失败再退回原地址。
- **黄果旧站详情走镜像配置**：详情页原来写死 `huangguo.video` 常量，远程镜像和用户配置对它都不生效；现在与黄果 AI 一致走 `providerBaseURL`。
- **浏览器指纹客户端跟随显式配置**：指纹传输原来只认死 `huangguo.video`，配置了自建镜像/联调地址会退回普通 client（过不了 Cloudflare，也连不上自签证书站点）。
- **代理探测不再空指针**：`proxyRouter` 未初始化时（纯直连场景）调用会 panic，补了判空。
- **回归门禁清零**：`go test ./core` 原有 6 个失败全部定位并处理——3 个是实现缺陷（无扩展名 M3U8、黄果旧站配置不生效、`proxyRouter` 空指针），3 个是用例本身过期或隔离不足（schema 版本、多分类 fixture、包级镜像缓存跨用例泄漏）；另外修掉榜单用例依赖真实 jsDelivr 的偶发失败。

## 七、常见问题

**Q：为什么剧库更新要很久？**
A：更新需要逐部复查详情。红果 2600 多部约 11 分钟、黄果 AI 2200 多部约 18 分钟，而单轮上限 10 分钟，所以会分批续跑。0.7.1 已把后台自动更新改为 2 小时间隔、可关闭；手动更新仍可随时执行。

**Q：黄果几个源有时更新失败？**
A：属网络可达性问题，不是解析错误 —— 黄果视频走 IPv6 且无备用域名，黄果 AI 的镜像域名会被重置。换网络或开代理后重试通常能恢复。

**Q：调了亮度，手机屏幕亮度没变？**
A：设计如此。只调整视频画面亮度，不动系统亮度，退出播放器后手机亮度不受影响。

**Q：为什么只提供 64 位安装包？**
A：目标设备（手机与投影仪）均为 arm64。32 位构建脚本保留，但不再发版。

**Q：支持电视 / 电脑吗？**
A：Android TV 已恢复适配（0.8.0）：遥控器导航、电视布局、过扫描安全边距、32 位盒子支持。Windows 版源码保留但当前不构建、不交付。
电视安装包用 `python3 scripts/build_android.py --tv --universal --all-sources` 构建（产出 arm64、armv7 分包，并额外产出包含两种 TV ABI 的 `-all.apk`）。若电视没被自动识别为电视（部分盒子定制 launcher、投影仪），在「更多 → 界面模式」里手动选「电视 / 遥控器」。

**Q：需要登录吗？**
A：不需要。没有云端账号；本机用户管理只用于区分不同使用者与权限。

## 十、开发与构建

环境：Flutter `3.47.4`、Dart `3.12+`、Go `1.24.1+`、Python `3.10+`；Android 需 JDK 17、SDK 36、NDK `28.2.13676358`。

```sh
# 全站源版（真果鉴TV）
python3 scripts/build_android.py --abi arm64-v8a --all-sources
# 仅红果版（红果鉴）
python3 scripts/build_android.py --abi arm64-v8a
# 电视版（arm64-v8a + armeabi-v7a 分包，并额外产出 universal/all APK）
python3 scripts/build_android.py --tv --universal --all-sources
```

- **必须在纯英文路径下构建**（中文路径会导致工具链失败）。
- 构建时不要设 HTTP 代理；访问 GitHub 时才需要代理。
- 产物在 `dist/android/`，`SHA256SUMS.txt` 为校验清单。

不用本机编译时，走 **Actions → Build APK → Run workflow**：`all_sources` 决定真果鉴TV / 红果鉴，`tv` 产出 arm64-v8a + armeabi-v7a 分包，`universal` 额外产出合并 APK（只含 ARM 两套 ABI）；跑完在本次运行的 Artifacts 里下载 `apk-<run_number>.zip`。工作流固定 Flutter `3.47.4`、Go `1.24.1`、NDK `28.2.13676358`，与本机脚本一致；出包后会自动用 `apksigner` / `zipalign` / `aapt2` 验一遍签名、对齐与 ABI；未配置 `android/key.properties` 时用 debug 签名，可直接安装但不适合上架。

源码结构：

| 目录 | 内容 |
| --- | --- |
| `lib/` | 页面、播放器、本地用户、FFI、下载与媒体处理 |
| `native/core/`、`native/bridge/` | Go 站源核心、缓存、下载与 C ABI |
| `android/`、`windows/`、`ios/` | 平台工程与必要资源 |
| `scripts/`、`.github/workflows/` | 构建、签名、验证与版本快照 |
| `test/`、`integration_test/` | 自动化与设备回归 |

仓库只提交业务源码，不包含构建产物、依赖缓存、本地机器配置、签名文件与任何密钥。

播放器使用 [media_kit](https://github.com/media-kit/media-kit) / libmpv，合并与导出使用 [FFmpegKit min-gpl](https://github.com/sk3llo/ffmpeg_kit_flutter)（含 FFmpeg、x264 / x265 等 GPL 组件，适用上游许可证）。
